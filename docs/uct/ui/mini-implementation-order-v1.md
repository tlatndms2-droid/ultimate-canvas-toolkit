# Mini 구현 순서 시각 요약

기획 초안, 2026-10-26. 이미지 설명 형식 선호에 따라 작업 순서를 그림으로 남김.
현재는 계획 단계이며 코드 변경은 하지 않음.

## 기존 코드를 재사용하는 통합 순서

| 단계 | 실행 내용 | 기존 코드 활용 기준 |
|---|---|---:|
| 1. 기존 플러그인 코드를 UCT에 합치기 | 각 저장소의 이미 동작하는 진입점·화면·처리 모듈을 가져오고, 명령·설정·스타일 ID 충돌만 연결 | 재사용 우선 |
| 2. 공통 Canvas 문맥 연결 | Portal의 현재 가상 공간을 Mindmap·Outliner·Palette가 함께 보도록 현재 graph 접근점 연결 | 필요한 연결부만 변경 |
| 3. 기존 Mini를 새 Storage 흐름으로 바꾸기 | floating Mini UI와 저장소를 기반으로 기존 Workspace 구조를 폴더로 옮기고 형식별 보기·검색 범위를 연결 | 새 화면을 통째로 다시 만들지 않음 |
| 4. Mini 배치·미디어·백업 보강 | 기존 수집/잘라내기·그룹 직렬화·위치 계산·삭제를 유지하면서 이동/Shift 복사, 독립 미디어, 수동 백업/복구 추가 | 추가 계약 부분만 구현 |
| 5. 입력과 메타데이터 연결 | 이미 있는 Enter·Portal 키 처리에 형식별 분기 추가. Palette 라벨/캡션을 Outliner와 검색에 노출 | 충돌 지점만 조정 |
| 6. 통합 검증 | 빌드·Sandbox 실행·시안 확인·핵심 조작·재시작 보존 | 통합 결과 확인 |

앞서 적었던 **6시간 50분–11시간 40분은 철회한다.** 기존 구현을 재사용하는 이식/연결 작업을 새 기능 전체 제작으로 계산한 잘못된 추정이었다. 이 문서에서 신뢰할 만한 시간을 다시 산정하지 않는다.

**프로그램 영향(예상, 미측정):** CPU 낮음~중간. 기존 타이머/화면 갱신 중복을 정리하면 낮출 수 있지만 통합만으로 자동 감소하지 않는다. 메모리 중간: 보관 미디어와 PDF 미리보기 cache가 사용. 저장 공간은 수집한 원본 미디어 용량만큼 증가. 백업 때 일시적으로 백업 크기만큼 추가 공간과 디스크 쓰기. 네트워크 상시 사용 없음. 화면 반응성은 큰 보관함에서 검색/미리보기 범위를 제한하는 구현에 좌우된다.

## 현재 선행 조건과 멈춤 기준

현재 폴더에는 조사 문서와 고정 커밋 소스 스냅샷이 있고, UCT 실행 코드 및 원격 저장소는 없다. 그러므로 1단계는 이미 만든 기능을 새로 개발하는 일이 아니라 기존 구현을 실제 UCT 대상 경로에 옮겨 한 앱으로 연결하는 일이다. 패키지/빌드 구조와 스타일 파일은 스냅샷 범위 밖이므로 대상 경로를 정한 뒤 그 저장소 절차에 맞춰야 한다.

기존 데이터 구조가 예상과 달라 이름·상위/하위 관계·직접 소유 항목을 보존할 수 없는 경우 이관 규칙을 임의로 바꾸지 않고 멈춘다. 원본 Canvas/보관 자료가 손실되거나 재시작 후 유지되지 않는 검증 실패에서도 다음 단계와 배포를 멈춘다. Mini 자료의 자동 백업이나 과거 버전 보관은 추가하지 않는다.

## 이 범위에 포함되지 않는 것

- 현재는 코드 수정·저장소 생성·빌드·Sandbox 설치를 하지 않았다.
- 실제 사용자 Vault의 기존 Side/Workspace 자료를 아직 읽지 않았다. 이관 결정은 구조 규칙이며 실제 변환은 미실행이다.
- 이미지 시안은 동작 설명 자료이며 완성된 앱 화면 또는 구현 결과가 아니다.
- 공개 Release/BRAT는 UCT 저장소와 배포 대상이 정해지지 않아 이 계획의 소요 시간에 넣지 않았다. 코드 작업이 승인되면 프로젝트 지침에 따라 검증 후 정리한다.
