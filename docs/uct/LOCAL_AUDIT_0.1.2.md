# UCT 0.1.2 로컬 검증 결과

2026-10-27 · 공개 배포 없음 · Obsidian 1.14.5 · UCT-Integration-Sandbox

## 수정한 문제

- Storage 접기/펼치기를 같은 크기의 아이콘 버튼으로 통일했습니다.
- 폴더·Collect·형식별 목록에 각각 아이콘을 붙였습니다.
- 상위 폴더 수량에 모든 하위 폴더의 자료를 포함합니다. 접어도 합계가 유지됩니다.
- Mini 제목과 본문은 Obsidian 인터페이스 글꼴을 사용하고 선택 색상은 시스템 강조색을 따릅니다.
- 여러 자료와 포탈을 함께 잘라낼 때 ‘첫 포탈’로 잘못 분류하던 것을 ‘묶음’으로 고쳤습니다. 기존 33개 항목 자료도 전체가 표시됩니다. 실제 저장 그래프는 바꾸지 않았습니다.
- 포탈 생성·복제·해제·다른 공간 배치 과정에서 라벨과 캡션 저장 위치를 연결했습니다.
- 포탈 진입 직후 첫 Shift+Enter가 누락되던 PDF 입력을 선택 파일에서 바로 열도록 고쳤습니다.
- 내용 검색과 라벨 전용 검색을 분리했습니다.
- 독립 링크 포탈과 일반 파일을 함께 보관한 묶음에서도 일반 파일 이름 변경·삭제가 반영되도록 고쳤습니다.
- 잘라낸 자료의 수집 Canvas 경로, ZIP 복구된 구형 묶음 표시, 제거된 태그의 편집창 제목을 정리했습니다.

## 확인 방법과 한계

- 키보드·클릭·드래그는 격리 Sandbox에서 실행했습니다. 검증용 자료 준비와 결과 읽기는 앱 API를 병행했습니다.
- PDF는 창 생성뿐 아니라 페이지 canvas 렌더 완료, 이미지의 실제 로드, 음성·영상의 재생 가능 상태를 확인했습니다. 기존 33개 자료 묶음은 전체 노드 수와 캡처를 확인했습니다.
- ZIP 백업/복구 및 이미지 폴더 내보내기는 실제 처리 코드를 실행했습니다. OS 파일 선택 창의 반환 경로만 검증 폴더로 대체했습니다. 따라서 OS 파일 선택 창을 사람이 직접 클릭한 검증으로 주장하지 않습니다.
- 저장 실패 검사는 Canvas 저장 지점에 한 번의 오류를 주입해 실제 복구 경로를 확인했습니다.
- 초기 실패 기록 일부는 비동기 저장·화면 전환 완료 전 읽기, 잘못된 CSS 선택자, 자동 번호가 붙는 발표 영역 이름 비교에서 발생했습니다. 완료 상태를 기다리고 실제 필드·화면을 대조해 재검증했습니다. 원시 기록은 삭제하지 않았습니다.
- 외부 웹사이트/YouTube 서비스 자체의 응답과 모든 원본 플러그인 기능 조합을 전수 검사한 것은 아닙니다. 이번 확정 동작의 검증 경로를 위 목록으로 명시했습니다.

## 검토 위치

Sandbox의 ‘0.1.2 실동작 검증’ 폴더를 열어 두었습니다. 상위 수량 6개는 직접 항목 4개와 하위 폴더 2개의 합계입니다. 기존 사용자 자료 2개는 남겨 두었고, 검증용 복구 중복 항목은 정리했습니다. 원본 자료 백업과 검사 증거는 프로젝트의 .validation/audit-20261027에 보관했습니다.

GitHub push, Release, BRAT 업데이트, 원본 저장소 삭제는 실행하지 않았습니다. 공개 최신판은 이전 0.1.1이며 이번 0.1.2는 로컬 검증본입니다.
