# 조사 범위와 신뢰 수준

## 수행한 것

2026-10-26 GitHub 연결 도구로 7개 저장소의 tree와 manifest를 읽고, 각 기준 커밋의 src TypeScript/CommonJS와 선택 문서 110개 파일을 reference/snapshots에 보관했다. 정확한 파일·blob·커밋 목록은 reference/SOURCES.json에 있다.

각 플러그인의 진입점, 명령/키 처리, 주요 저장 모델, Canvas 접근, 대상 기능 흐름, 반복 작업과 해제를 중심으로 정적 분석했다. Palette는 수집·잘라내기·그룹 저장/복원·배치·삭제·metadata·store 소유권을, Portal은 가상/링크 공간과 저장을, Outliner는 표시 자격·상태 키·검색을 중심으로 추적했다. Visibility 편집기 의존성, Mindmap 입력·생성·미디어, PDF 렌더 pool과 키 처리, Image Copy 파일 export도 확인했다.

## 수행하지 않은 것

전체 Git 저장소 미러/모든 테스트/빌드 산출물/CSS/이미지의 완전 수집이 아니다. 보관된 모든 보조 함수의 모든 분기를 줄 단위 완전 증명한 것도 아니다. 원본에 있는 README/HANDOFF의 역사적 성공 기록은 이번 실행 증거로 쓰지 않았다.
최초 정적 조사에서는 실제 Obsidian 실행·코드 변경·빌드·설치·성능 측정·배포를 하지 않았다. 후속 사용자 요청으로 격리 Sandbox에 기존 Portal 0.4.10과 PDF Viewcard 0.1.2를 설치하고 Ctrl+Enter를 실제 입력했다. 포탈 내부 PDF에서 바깥 복귀와 큰 미리보기가 함께 실행되는 것을 확인했다. 당시 앱은 Obsidian 1.12.7이며 전체 UCT 통합, 사용자 Portal/Outliner 문제 재현, 재시작 호환성 검증 결과는 아니다.

## 주장 수준

- 코드 사실: 함수·조건·저장 필드·주기처럼 확인 가능한 현재 소스.
- 사용자 결정: DECISIONS.md. 현재 소스가 다르더라도 요구를 취소하지 않는다.
- 설계 제안: 공통 어댑터/입력 라우터/asset 보관 등. 아직 구현하지 않았다.
- 위험 추론: 파일 경로 기준 Outliner와 가상 Portal의 불일치 등. 재현 전 원인 확정이라고 부르지 않는다.

## 재사용과 갱신

현재 자료는 고정 커밋까지 유효하다. 나중에 같은 주제를 물을 때 원격 전체 소스를 다시 받지 말고 분석 문서와 필요한 함수부터 확인할 수 있다. 실제 수정 시작 또는 코드 변경 증거가 있을 때 커밋 차이의 관련 파일만 확인해 갱신한다. 단축키 우선순위·원본 삭제·저장 경계처럼 실행 결과가 필요한 항목은 그때 실제 검증한다.

## 저장 결과 확인

110개 스냅샷 파일을 git hash-object --no-filters로 계산하여 GitHub tree의 blob SHA와 대조했고 모두 일치했다. 새 프로젝트 안내/분석 문서 14개의 상대 링크는 모두 존재하는 파일 또는 폴더를 가리킨다. 이 검사는 자료 저장 정확성 확인이며 플러그인 실행 검증이 아니다.

## 프로젝트 메모리의 사용

이 프로젝트는 PROJECT_MEMORY.md와 AGENTS.md 색인으로 재사용 가능한 기록을 갖춘다. 앱의 개인 메모리와 별개이며 “전 대화를 자동으로 정확히 기억한다”는 약속이 아니다. 공식 문서의 AGENTS.md는 작업 위치에 따라 읽히는 프로젝트 지침 진입점이다.
