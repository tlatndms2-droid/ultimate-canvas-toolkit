# 사용자 결정 기록

출처: 현재 대화에서 사용자가 직접 말한 선택과 승인. 코드 사실과 분리한다.
기록일 2026-10-26. “다음 진행”은 당시 기획 단계를 잇는 말이며 전체 코드 구현 승인으로 확대하지 않는다.

## 통합 범위

이름 **Ultimate Canvas Toolkit**.
Mindmap, Outliner, Portal, Image Copy, PDF Viewcard, Visibility의 Enter 편집기, Canvas Palette의 Mini 기능을 통합한다.
Visibility의 접기 기능, 기존 Palette의 Side Palette 및 Workspace, 태그 기능은 제거 방향이다.
라벨·캡션은 유지한다. 별도로 제거 결정하지 않은 기존 Mindmap/Outliner 기능을 임의 축소하지 않는다.

## UCT 저장소와 기존 저장소 삭제 조건

사용자가 기반 저장소 선택의 1번인 **UCT 전용 새 저장소**를 선택했다. 기존 Canvas Palette 저장소 자체를 UCT로 바꾸는 방식은 선택하지 않았다. 이 선택은 통합 대상 저장소의 방향을 정한 것이며 저장소 생성·코드 구현·공개 배포 완료 기록이 아니다.

사용자가 직접 **“완성됐다”라고 말한 뒤에만** 통합 대상인 기존 개별 플러그인 저장소를 삭제한다. Codex의 구현 완료 보고, 검증 통과, Release 또는 BRAT 성공만으로 이 조건을 충족했다고 판단하지 않는다. 현재 삭제를 실행하지 않는다.

삭제 범위는 이번 UCT 통합 대상 7개다: `obsidian-advanced-mindmap`, `obsidian-canvas-outliner`, `obsidian-canvas-portal`, `obsidian-canvas-visibility`, `canvas-image-copy`, `obsidian-canvas-pdf-viewcard`, `canvas-palette`. UCT 저장소와 통합 대상이 아닌 다른 저장소는 이 지시에 포함되지 않는다.

## Portal · Outliner · 라벨/캡션

- 각 Portal을 개별 Canvas 공간으로 취급한다. Canvas A에서 작업공간 Portal에 들어가면 그 내부 항목만 Outliner에 표시한다. 그 안에 참고자료 Portal이 있으면 Portal 항목만 표시하고, 그 안에 진입하면 참고자료 내부 항목으로 전환한다. 모든 중첩 깊이의 항목을 바깥 목록에 한꺼번에 펼치지 않는다. 링크 Portal은 대상 Canvas 파일의 독립 공간으로 표시한다. 이 해석은 사용자가 제공한 흐름 그림에 적은 결정이며 다시 묻지 않는다.
- 라벨 있는 아이템은 현재 공간 Outliner 표시 대상에 자동 포함한다.
- Outliner에 라벨/캡션 표시, Canvas Search에 라벨 검색 포함.
- Outliner의 라벨·캡션은 확인 전용이다. 수정은 Canvas에서 한다. 사용자가 선택한 확정 사항이다.
- 라벨 생성은 **Alt+L**로 기존 Canvas Palette의 라벨 선택·생성 창을 연다. 기존 라벨을 고르거나 새 이름과 색을 지정해 적용한다. 태그 영역은 제거 대상이라 새 창에 포함하지 않는다.
- 캡션 생성은 **Alt+C**로 선택 카드 바로 아래 입력란을 연다. 기존에 합의한 카드 아래 `+`도 같은 입력란을 여는 경로다. Outliner에서는 라벨·캡션을 확인만 하고 수정은 Canvas에서 한다.
- 기존 라벨 창을 재사용하고 캡션은 카드 아래에 입력하는 흐름을 사용자가 확인했다. 라벨·캡션 단축키는 글 입력 중에는 실행하지 않는다.
- 캡션은 카드 아래에 마우스를 가까이 가져가면 +가 나타나고 선택하여 아래에 생성하는 경로도 제공.
- 같은 플러그인이라는 이유만으로 메타데이터 전달이 자동 구현되지는 않는다. Mini 저장 스냅샷에 라벨·캡션을 명시적으로 포함한다.

## Mini의 역할과 UI

Mini는 Canvas 자료를 수집하여 보관했다가 다른 위치에 옮기는 독립 도구다. Outliner 제어 도구가 아니고 원본과 계속 동기화하지 않는다.

화이트 테마, 갤러리형 디자인, 카드 보기/목록 보기 전환.
왼쪽 Storage는 접을 수 있다. Collect는 수집함으로 유지하고 사용자 폴더 목록과 폴더와 무관한 전체 형식별 보기를 제공한다.
폴더 선택 시 중앙에는 선택 폴더 내용과 위치가 보인다.
오른쪽 상세는 항목을 선택했을 때만 슬라이드로 열리며 선택 전에는 빈 영역을 차지하지 않는다. 실제 Canvas와 유사한 큰 미리보기, 수집일·수정일·수집 위치·라벨·캡션을 표시한다.
폴더 하위 구조와 접기/선택 조작은 기획 연속 대화의 정리 기준이며, 추가 세부 UI는 실제 시안 단계에서 좁혀 정한다.

## 수집 · 보관 · 배치 · 삭제

### 검색 범위 확정 · 2026-10-26

현재 보고 있는 목록 안에서 검색하고, 필요할 때 전체 검색으로 전환한다. 전체 검색은 Collect와 모든 Storage 폴더를 포함하며 결과에 보관 경로를 표시한다. 사용자 선택 응답으로 확정했다. 설명 이미지: ui/mini-search-scope-proposal-v1.png. UCT 0.1.0에 구현했다.

### 수집과 배치

- Canvas→Mini는 기존 수집/잘라내기 조작을 재사용한다.
- Collect에서 Storage 폴더로 드래그하면 이동하고 Collect에서는 빠진다.
- Mini→Canvas **일반 드래그는 이동**: 배치 성공 뒤 Mini에서 제거.
- **Shift+드래그는 복사**: Canvas에 배치하고 Mini에는 유지.
- 배치 중 오버레이로 위치를 미리 보고 정한다. 마우스를 놓아 확정, Esc로 취소하는 흐름.
- 함께 배치하는 별도 자료끼리는 겹치지 않는다. 기존 묶음 내부 좌표·연결 보존을 다시 선택받지 않는다.
- 네 개의 복사/이동 버튼을 만들지 않는다.
- 항목 삭제는 현재 Mini의 기존 삭제 조작을 재사용한다.
- 사용자가 확정: 폴더를 삭제하면 내부의 아이템은 전부 미분류로 이동한다.
- 사용자가 확정: 삭제 폴더 안의 하위 폴더도 미분류 안에 그대로 둔다. 따라서 아이템은 모두 미분류에 속하며, 하위 폴더 위치와 그 안의 자료 구조가 보존된다.
- 재시작 후 유지 기능은 이미 존재한다. 이를 신규 강화로 반복 제안하지 않는다.
- 최신 확정: 일반 이미지/PDF 등 파일 항목은 원본에 연결한다. 원본 파일 삭제 시 해당 Mini 항목도 삭제하며, Canvas 카드 삭제·잘라내기는 파일 삭제로 취급하지 않는다. 파일 이름·위치 변경을 따라간다. 링크 포탈만 아래 독립 보관 예외를 적용한다. 원본 내용과 지속 동기화하지 않는다.

## 링크 포탈 독립 보관 확정 · 2026-10-26

사용자가 B를 선택했다. 링크 포탈을 Mini에 수집할 때 수집 당시 대상 Canvas 내부 내용과 필요한 파일까지 독립 보관한다. 원본 위치만 보관하는 A는 선택하지 않았다. 재배치 시 보관본으로 독립된 포탈을 구성하며 원본 변경을 따라가지 않는다. 원본 Canvas 파일 자체를 수집 중 삭제한다는 의미가 아니다. 내부 링크의 순환·중복 참조와 파일 누락은 구현 단계에서 처리할 기술 사항이다. 설명 이미지: ui/mini-link-portal-storage-options-v1.png. UCT 0.1.0에 구현했다.

## 기존 자료 이관 확정 · 2026-10-26

사용자가 이미지의 1번을 선택했다. 실제 기존 Side/Workspace 자료가 있다면 Workspace 이름을 새 Mini Storage의 최상위 폴더로 옮기고, 하위 폴더 및 폴더가 아닌 직접 소유 자료의 위치를 보존한다. 기존 Mini Collect 자료는 Collect에 남긴다. 실제 데이터가 없어 이관할 항목이 없으면 이 과정은 생략한다. 설명 이미지: ui/mini-workspace-migration-proposal-v1.png. UCT 0.1.0 이관 코드와 합성 자료 테스트로 확인했다. 실제 사용자 Vault 이관은 실행하지 않았다.

## 백업 파일 저장 위치 확정 · 2026-10-26

백업 ZIP을 만들 때마다 사용자가 저장 위치를 선택한다. ZIP 안에 Mini의 폴더·자료·필요 미디어를 담고, 복구 때는 사용자가 ZIP을 골라 별도 복구 폴더에 내용을 추가한다. 기존 자료는 덮어쓰지 않는다. 백업 진입은 앞서 확인한 화면의 Storage 왼쪽 아래 `백업` 항목을 재사용하고, 누르면 `백업 파일 만들기`와 `백업에서 복구`를 고르는 흐름으로 설계한다. 저장·복구 시각 흐름은 `ui/mini-backup-flow.html`.

## 수동 백업 · 복구 규칙

사용자가 명확히 자동 백업/과거 시점 보관을 거절했다. **Mini는 수동 백업만** 한다. “10개 보관”, 주기 백업, 자동 스냅샷을 다시 도입하지 않는다.
백업에는 폴더·항목·라벨·캡션과 작동에 필요한 미디어 파일을 포함하는 방향이다.
복구는 기존 자료에 곧바로 합쳐 섞지 않고 **별도 복구 폴더를 만들어** 넣는다. 백업 안의 폴더 구조와 Collect 자료도 그 복구 공간 안에 보존한다. 기존 자료를 덮어쓰지 않는다.
복구 폴더의 날짜·시간 명칭은 충돌 회피를 위한 표시 방법이지 과거 시점을 자동 보관하는 기능이 아니다.

## PDF 큰 미리보기 단축키 확정 · 2026-10-26

PDF 카드의 Enter는 기존 읽기 전환을 유지한다. 큰 미리보기는 기존 Ctrl+Enter에서 **Shift+Enter**로 바꾼다. Ctrl+Enter는 Portal 입장·복귀에 사용한다. Esc는 큰 미리보기를 닫는다. 더블 Enter 제안은 채택하지 않았다. UCT 0.1.0에서 Shift+Enter로 변경하고 격리 앱에서 확인했다.

Sandbox에서 Portal 0.4.10과 PDF Viewcard 0.1.2를 함께 로드해 실제 Ctrl+Enter 입력을 확인했다. 바깥 PDF에서는 큰 미리보기가 열렸고, 포탈 내부 PDF에서는 바깥 복귀와 PDF 큰 미리보기가 함께 실행됐다. 격리 시험 환경에서 확인한 결과이며 다른 버전·Vault 전반을 확인한 것은 아니다.

## 혼동 방지

새 Mini의 왼쪽 Storage UI는 제거할 구형 Side Palette 기능과 다르다.
수동 백업과 평소 자동 저장은 다르다. 앱을 끌 때 자료가 남게 하는 기본 저장을 없애는 것이 아니다.
자료 분류 라벨은 태그 제거와 별개로 유지한다.
기존 구현에서 발견한 기능을 새 요구나 미정 질문으로 다시 돌리지 않는다.


## 구현 전 완료한 나머지 기준

- 자료 정렬: 기존 수정일·이름 오름차순/내림차순.
- 복수 선택: 기존 Ctrl·Shift 선택 계산 재사용.
- 폴더 순서: 기존 순서 보존, 새 폴더는 뒤에 추가.
- 링크 포탈 사본: Obsidian 첨부파일 저장 위치에 고유 이름으로 생성, 덮어쓰지 않음.
- 이 범위의 사용자 선택은 완료. 구현 중 합의된 동작을 바꾸어야 할 때만 해당 부분을 멈추고 먼저 결정한다.
