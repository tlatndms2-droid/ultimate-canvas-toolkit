# UCT 0.1.12 — Mini 실제 성능 개선

2026-10-28. 사용자 승인 범위: 측정에 그치지 않고 확인된 성능 병목 수정. 배포/push/Release/BRAT 미실행.

## 원인과 변경
기존 CPU 프로파일의 Mini render 샘플309개 중282개가 마지막 scrollTop 대입 시점에 집중됐다. 이 대입은 누적된 레이아웃 계산을 강제한다. 화면 밖의 항목도 모두 내부 배치를 계산하는 것이 병목이었다. 썸네일 지연 생성만으로는 이 계산을 줄이지 못했다.

src/styles.css에 content-visibility:auto와 contain-intrinsic-block-size:auto를 적용했다. 화면 밖 항목의 내부 배치·페인트를 브라우저가 미루며, 한 번 표시한 항목의 실제 높이를 기억한다. 전체 DOM과 자료 순서, 범위 선택, 드래그 대상, 기존 썸네일 생성·해상도는 유지한다. 저장 형식·파일·사용 동작은 변경하지 않았다.

최종0.1.12로 같은 Sandbox를 재시작한 후, 동일 자료·창·설정에서 개선 CSS만 끄고 켜기를 번갈아 각각3회 실행했다. 아래는 중앙값(ms). CSS를 끈 상태는 직전 버전과 동일한 항목 레이아웃 처리다. 준비된 카드 복제 자료로 비교했으며, 모든 종류 파일의 다운로드·미디어 로딩 완료 시간은 아니다.

## 실제 앱·자료 확인
- 타입 검사·빌드·21개 관련 검사 통과.
- 동일 Sandbox 프로세스 재시작, runtime0.1.12 확인. 소스/설치3파일 SHA256 동일.
- 실제 스크롤로500번째 항목 도달, 첫 항목→마지막 항목 Shift클릭으로500개 선택.
- 마지막 항목 더블클릭으로 큰 미리보기1개 생성, Esc닫기.
- 실제 검색 입력 결과 perf-499 단1개 반환.
- 카드 보기 마지막 항목의 썸네일 표시 확인. 전체500항목DOM 유지, 화면 이동 중 필요한 preview host14개.
- 목록/카드 하단 실제 캡처 확인. 시험 자료는 메모리에서만 구성하고 원래 library로 복원했다.
- 검증 후 원래51개 항목·폴더 JSON 동일. Sandbox에 Mini를 열어 둠.
