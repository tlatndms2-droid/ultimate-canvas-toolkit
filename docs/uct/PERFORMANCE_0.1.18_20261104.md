# UCT 0.1.18 로컬 개선·검수 결과 — 2026-11-04

전체 성능 목표는 **미완료**다. 개선 코드는 바탕화면의 secondbrain - 복사본 2에 설치했다. 원본 Secondbrain, Canvas Drawing, 공개 배포는 변경하지 않았다.

## 구현한 변경

- Mini: 저장 완료 때 내용이 같으면 전체 화면을 다시 만들지 않는다. 카드/목록 전환과 기존 카드로 가능한 검색은 썸네일 DOM을 재사용한다. 정렬은 화면에 즉시 반영한다.
- 공통 보호 저장: 이미 있는 복구 사본의 불필요한 디렉터리 확인을 줄이고 독립적인 부가 파일 작업을 함께 처리한다. 기존 검증·fsync·보관 개수는 유지한다.
- Mini 추가 저장: 알려진 Obsidian 1.15 저장 함수에서 중복된 큐 앞 대기만 제거한다. 네이티브 저장 상태 머신은 유지한다. 실제 큐 실행 직전에 파일·경로·Canvas가 그대로인지 검사한다. 알 수 없는 저장 함수는 기존 경로를 사용한다.
- Portal: 전환 전 저장은 유지한다. 전환 후 내용이 같을 때만 중복 저장을 생략한다.
- 편집기/컴포지션: 분리된 Markdown leaf를 불필요하게 활성화하지 않고, 레이아웃 측정을 프레임 단위로 병합한다.
- Outliner: 동시에 열기 요청이 와도 같은 생성 작업을 공유하고, 이미 저장된 sidebar leaf를 재사용한다. 재로드 후 기존 3개 패널이 추가로 늘지 않는 것을 확인했다.
- 라벨/캡션의 외부 입력창 실험은 실제 지연 개선이 없어서 제품 코드에서 되돌렸다.

## 원인과 개선 효과의 범위

이전 첫 배치 85.36초의 대부분은 네이티브 전역 저장 큐 대기와 렌더러 응답 지연에 걸려 있었다. 복구 사본 파일 처리 시간만으로 전체를 설명할 수 없었다. 기존 저장 경로/수정 경로 ABBA 시험은 실행 순서와 최초/후속 편차가 커, 전체 Mini 개선율을 확정하지 못했다. 이번 0.726초를 이전 4초 또는 85초와 직접 비교해 개선율로 보고하지 않는다.

기존 공통 Canvas 엔진의 중복 계산 감소는 COMMON_CANVAS_RUNTIME_20261103.md의 동일 자료 ABBA 근거를 재사용한다. 전체 앱 속도가 같은 비율로 개선됐다는 뜻은 아니다. 외부 플러그인 임시 분리에서는 일관된 개선이 없어 특정 외부 플러그인을 원인으로 확정하지 않았다. 47개 플러그인을 복구했다.

## 보존·미검증·제외

- Mini 기존 31개 자료 전체 일치, 검수 폴더 삭제, pending 0, 변경 설정 원복을 확인했다. 파일 순서/객체 속성 순서의 직렬화 차이는 카드·좌표·연결·메타데이터의 의미가 같은지 대조 후 원래 바이트로 복구했다.
- 재시작 후 상태는 final-restart-proof.json에 기록한다. 원본 3개 파일 복구 근거는 final-source-restoration.json, Mini 결과는 final-visible-placement.json, 편집기 결과는 optimization-editor-proof.json.
- 실패: 표의 목표 초과 항목과 Mini 배치. 사용자 체감 전체 무지연/모든 목표 달성은 입증되지 않았다.
- 미검증: 이번 빌드에서 전체 대형 백업/복구와 장시간 미디어·대규모 누적 사용을 새로 전부 실행하지 않았다. 관련 기존 검증은 FINAL_VALIDATION_0.1.15.md에서 버전/범위를 구분해 재사용한다. 실제 한글 조합 입력과 물리 Shift 드래그의 새 수동 검수는 수행하지 않았다.
- 제외: 원본 Vault 변경, Canvas Drawing 수정, 공개 Release/push/BRAT, PDF 주석, 새 저장 형식/UI 재설계.

잔여 개선 대상은 Mini의 0.50초 초과, Portal/링크 Portal의 저장·전환, Mindmap과 편집기/컴포지션의 화면 준비, 발표/Remote 및 검색의 변동 지연이다. 검사 통과나 내부 함수 개선을 전체 완료로 대체하지 않는다.
